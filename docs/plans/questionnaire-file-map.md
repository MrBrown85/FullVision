# A map of `teacher/report-questionnaire.js`, for its split

Line numbers are for `origin/main` at commit `5975d7e9` (the commit this branch starts from). The file has 9,017 lines. This is a reading job: no code changed. It answers "Map `teacher/report-questionnaire.js`; no one has" (`docs/plans/handoff-review-plan.md`, Track E).

How the tables were made: a throwaway script (not committed) parsed the file with `acorn` as a script (it parses cleanly), took the module's top-level names, and walked every function with scope tracking so a local that shadows a module name is not counted. It tells reads from assignments (`x = …`) from mutations (`x[k] = …`, `x.push(…)`, `delete x[k]`). A second script did the same for free globals. Unit coverage came from a throwaway run of the 48 test files that touch the file (not the full suite), with V8 precise coverage switched on. Type-error counts came from a throwaway copy of the file with `// @ts-check` on top, run through the repo's own `tsconfig.json`. Counts are mechanical; the plans in section 6 are judgment.

## 0. Short version

- The file is one closure with 420 functions and 108 module-level variables, in 43 banner sections plus a 20-line header. The banners cover every line from 31 to 9,016. Two banners hide more than they say: "Browse Sentences: the cases" holds 1,109 lines (the cases, the sheet, and `tqSentences`, the one front door for every click on the Sentences card), and "The class's lines" holds 754.
- 63 of the 108 variables are shared state; 45 are constants private to one section. The knot is eleven "what is open" variables (`_wording`, `_addAt`, `_own`, `_browse`, `_supportMenu`, `_langMenu`, `_limitOpen`, `_lineEdit`, `_cal`, `_iePending`, `_drawer`) that about ten sections assign to. Most of the Sentences card sections (S21 to S40) cannot be split until those are one object.
- Easy pieces exist now: pure leaf sections with no shared state (about 1,660 lines in five pieces). The hubs (S1, S3, S21, S27, S29, S40) stay.
- The file never writes a score or a status. It reads marks, and it writes term ratings (comments, approvals, habits, attendance), report settings, and one course setting.
- The brief said new scripts are `<script src="/...">` tags. They are not: Reports' scripts are loaded on demand from `teacher/router.js` `_onDemand`. See section 7.

### 2c. What the table says

- `_activeCourse` is the only variable most sections read, and it is assigned in one place: `configure` (S1), which the host calls each time Reports opens or the class changes (`page-reports.js` lines 1603 and 2029). It can be handed to a piece as a value on each `configure` call.

## 6. A proposed split

### 6a. House method and prefix

- Prefix: `report-qn-` (the `report-one-*.js` family is the nearest example; this sorts the pieces next to `report-questionnaire.js`). Global names follow: `report-qn-browse-cases.js` makes `window.ReportQnBrowseCases`.
- Parent state injection, as `teacher/student-edit-dialog.js` (PR 1256) does it: the new IIFE declares `var _activeCourse;` and one-line shims named like the main file's helpers (`function _current() { return host.current(); }`), and a `configure(host)` that main calls from its own `configure`. The moved code then reads exactly the names it read before.
- The other direction (main calling a moved function) is a one-line pointer in main (`var browseCases = ReportQnBrowseCases.browseCases;`), as PR 1309 left pointers in `data.js`. Public keys on `ReportQuestionnaire` stay, so tests and `page-reports.js` change nothing.
- Each piece is one move-only PR with a proof. The proof used this week: parse the original main and the two new files with `acorn` (script mode), drop locations and comments, and show that the original IIFE body's statements, in order, are exactly main's statements after the move plus the moved statements, each tree identical, leaving only the lines written on purpose (new file's wrapper and `// @ts-check`, shims, pointers, the `configure` calls), which the PR lists.

## 8. What surprised me

**Dead code (proved by the walk; list only, nothing deleted).**

- The export `bothOpen` (line 8,971) is referenced nowhere in the repo: not in the file, `page-reports.js`, tests or browser specs.
- The walk found no function that nothing references and no variable that is never read. Six more exports (`browseOpen`, `earlierRow`, `metaFor`, `obsCounts`, `pronounChanges`, `writtenWith`) are used inside the file only; their export entries have no outside user.
- 35 functions are referenced only from the exports object (the handlers `page-reports.js` calls by name). They are live.

**Duplicated helpers.**

- `_dateOf` (lines 1,444 to 1,446) is character for character the same as `_dateOf` in `teacher/comment-bank.js` (line 2,413); two more copies exist in `teacher/class-results.js` and `teacher/assessment-copy.js`.
- `_cap` (line 707) is the same function as `_cap` in `teacher/comment-bank.js` (line 2,307).
- `_plural` has eight variants across `teacher/` (this one has an extra fourth argument). `_first` has five, `_today` four, `_courseName` two, `_longDay` and `_shortDay` one each elsewhere.
- `schoolYear` (S25) is a one-line forwarder to `CommentBank.schoolYear`.

**Hidden coupling worth knowing, not bugs.**

- `renderTermQuestionnaire` (S42) empties three other sections' caches by assignment (`_staleCache = {}`, `_claimCache = {}`, `_shared = null`, lines 8,666 to 8,668). If S9, S24 or S40 moved, that line would stop reaching them.
- Lines 22 to 26 reassign function declarations at load. The reassignment makes the wrapped function the one every caller in the file gets, so any move of those five functions must carry the wrapper line.
- The two document-level listener sets (sliders, row drag) are added once and stay for the life of the page, including after the teacher leaves Reports. They only act on their own selectors, so they are inert there.
- Banners understate: S38 is 1,109 lines under a banner that says "the cases" (the cases are the first 396 lines), and `tqEditStudent` lives in "Where This Information Comes From".
- Four tests read this file's text (section 5). A split breaks them in ways that look unrelated: one counts four `exclude: lastTermIds(...)` lines across S12, S21, S25 and S40.

**Looks like a bug.** I found none I can show. Every `data-action` the file writes (23) is handled in `page-reports.js`, every `data-do` it writes has a `case`, and the earlier-report tab guards a stale term id (line 2,352).

**What this brief got wrong.**

- New scripts are not `<script src>` tags in `app.html`; they go in the router's `_onDemand['/reports'].scripts` list, `sw.js`, `e2e/loading-on-demand.spec.js`, `scripts/lint-globals.mjs`, and `tests/setup.js`. `tests/docs-sync.test.js` does not apply.
- The differential run named as the proof for mark-touching moves does not exercise the Term Questionnaire.
- Moved code lands in the first `teacher/` files under `// @ts-check`; no teacher file is checked yet, so there is no house pattern for typing a page file. The 28 files in `tsconfig.json` give globals to the check; only four are `// @ts-check` themselves.
- The brief's size (about 9,000 lines) is right (9,017); the handoff plan's "8,994" is old.
