Observation cards

What ships today, then three directions that lean on FullVision's own vocabulary: the gradebook's tiles and tabular numbers, the dashboard's week squares, and the warm paper of the printed reports. Each is shown on the desktop feed and the phone Observe tab with the same five observations, and below each, the edit window that opens from a card (today: the lined cream notebook sheet), restyled to match. Sentiment colours, tags, Delete and the day grouping stay in every option; only the card's form changes.

ARegister

Borrowed from the gradebook. No boxes. One ruled list per day, like a class register or lab notebook: a fixed time column in tabular figures, a small square for the type (the same squares the dashboard uses for weeks), the name, then the note. Context and assessment follow the name as plain words; tags are a plain comma list. Densest of the three: about a third more observations fit on a screen, and your eye runs down the time column.

DIndex tiles · C with B's tabs

C's card, with B's word instead of a letter. The type is a small square-cornered block that says "Strength", "Growth" or "Concern", in the proficiency colour, at the start of the header line. The edit window is the same card grown larger, with the three types as tabs on its top edge (from B), a plain note box, FullVision's own segmented control for context, and tags. One shape from card to editor on both desktop and phone.

Web designerC's "S / G / C" needed a legend; abbreviations on a feed are a smell. A word in a 20 px block costs little width and reads instantly. The note is now the largest text on the card (15 px) so the content leads, not the name. The blue focus ring on C's note box was the last chat-app tell; it's a plain border now.
Experienced teacherScans for one student, then reads the note. Name stays bold at the front; "with Noor and Liam" and "Quoted in Report 1" stay visible because reusing a quoted note is the mistake to avoid. Date stays right-aligned and quiet.
New teacherDoesn't know what the letters mean, and wouldn't guess that a square is a type. Words fix that without a legend. In the editor the tabs make the choice obvious, Delete is quiet, Save is the one blue button.
Techie / non-techieTechie: Enter saves, Shift+Enter is a new line, the hint says so. Non-techie: 44 px tap targets on the phone, the whole card opens the sheet, nothing is swipe-only; Delete lives inside the sheet where it can be found.

D2Index tiles, round 2

The table: two designers, a 20-year teacher, a first-year teacher, and the two of them who never read a manual. Everything below changed from D; the reason is in each note. What stayed: the quiet white card, the word block for the type, the segmented control for context, Save as the one blue button.

Names line up. The type block is a fixed 74 px column, so every name starts at the same x. Designer: you scan a feed down one edge, not a ragged one. Teacher: I look for a kid, not a colour.
Time only, not the date. "Fri, Oct 16 · 12:00 p.m." repeated the day header above it. Now "12:00 p.m."; the day header gains a count. Designer: say each thing once. Teacher: "3 observations" tells me how the day went.
Delete hides until hover. Five trash cans down the feed were the loudest icons on the page, and the easiest misclick. Delete lives in the edit window; on desktop it also appears on hover (Mei's card). First-year teacher: I deleted a note once reaching for the scrollbar.
Context, assessment and tags look different. In D they were one grey run. Now the setting is lightest, the linked assessment is a link, the tags carry their dots and a darker grey. Teacher: tags go on the report, the setting doesn't; they can't read the same.
Tabs sit in a folder band, not on the backdrop. D's tabs floated over the dark overlay and the unselected ones nearly vanished. The band is part of the window, and the date moved into it. Designer: a tab needs an edge to attach to.
One way to leave. D had both × and Cancel. Cancel stays (and Esc); the × goes. Non-techie: two close buttons means I wonder if they do different things.
Editing a quoted note warns you. A line under the name: "Quoted in Report 1. Changes here show in that report." Veteran teacher: the one edit that bites. Nobody at the table had thought of it until she said it.
Context can be cleared. A segmented control implies one must be chosen. Tap the chosen one again to clear; the label says so. Teacher: half my notes have no setting.
Phone: Save in the header, Delete at the bottom. iOS form sheets put Cancel and Save in the top bar, above the keyboard; a full-width Delete sits last, where nothing is reached by accident. Non-techie: that's where every iPhone app puts it.
Phone: all five contexts, 44 px tall. D's sheet showed three; the control now wraps to two rows at thumb height. The card shows the time, like desktop, under a day header. Techie: "3d ago" on one screen and a clock on the other is two models.
Phone card gets a chevron. A faint › says the card opens. Designers split on it; the two non-techies settled it.
Solid blocks, not tinted. The table voted: solid matches the gradebook tile and the tab; tinted read as a pill again, which is what we're leaving. Designer: if 27 solid blocks feel heavy in use, that is one CSS line.

D3Round 3: the context picker

The segmented control was the wrong control. It takes a full row and a grey tray for a field most notes leave blank, and it looks like a mandatory choice. Context is now a small menu on the same row as the tags: "Independent ▾" when set, "+ Context" when not. One click opens a short list with None at the bottom. The editor loses a whole row; tags, which do go on the report, come first.

Why a menu and not chips. Five chips in a row is the segmented control again without the tray. A menu shows one word when set and nothing when not. Designer: the control should be the size of how often it's used.
Tags before context. Tags shape the report; context is a note to yourself. Left to right follows importance. Teacher: I'd pick a tag ten times before I'd pick a setting.
Phone: a settings-style row. "Context · Independent ›" opens the standard picker sheet. Tags keep their chips underneath, since they are tapped often. Non-techie: it's the row every iPhone settings screen uses.
Where it is still visible. The feed card keeps showing the setting in light grey at the start of the meta line, so nothing is hidden, only the control shrank.

D4Round 4: the capture strip and the phone quick menu

The strip is the edit window's twin. Today it is a bank of nine pill chips above a grey box, the same pill style the cards are leaving. Now it is the same folder-band card as the editor: the three types as tabs (none chosen until you pick one), a Student line like an email's To line, the note box, and one row underneath: + Starter, tags, the context menu, and a + Link menu that holds Assessment and Competency, which were two chips for something used once a week. Add stays the one blue button; Enter adds.

Student first. The student line moved above the box, as a To line. Teacher: who, then what. Designer: the old strip read "Select students…" like a form field; a To line reads like addressing a note.
Fewer chips, same powers. + Assessment and + Competency fold into + Link ▾; Keep tags becomes a small checkbox at the right. Designer: nine chips of equal weight say nothing is important. Veteran teacher: I link an assessment maybe once a week.
Starters show their type and tags. Today's list shows text and type; each row now shows the type block and, under the text, what it will set. First-year teacher: I didn't know a starter set tags until it had.
Phone quick menu: rows, not cards. Starters are one-tap rows with the type block in the same 74 px column as the feed, plus "Write your own…" which opens the D3 sheet. Non-techie: it looks like every other list on my phone.
Shorthand stays, hinted once. @name, #tag, !type and /starter still work in the box; the To line says "or type @name" so the techie finds it and the non-techie can ignore it.
Dropped: the "Context" prompt chip. In the old strip, Context sat beside the three types as a fourth pill, which made it look like a type. It is now the same small menu as the editor.
