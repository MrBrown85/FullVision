# Dashboard cards and student email (2026-11-05)

Colin's CSL reviewer (Nov 5) couldn't read the dashboard's student cards or its Curricular Competencies card. The canvas at https://claude.ai/artifact/CsoEaARt6PtijDCoNzq8Xk (private) holds the approved mockups at the dashboard's real sizes. This plan turns them into one pull request: Netlify credits are scarce, so everything lands in one branch, `feat/dashboard-cards`, and one merge.

Rules that hold throughout: grade math only in `shared/calc.js`; levels and grades displayed only through `formatLevel` / `studentGradeSummary`; every string into HTML through `esc`; no new innerHTML sites the audit can't prove (`npm run audit:html`); Title Case labels, plain sentences for hints; Demo Mode must show every feature. Pattern to follow for pop-ups: the dashboard's `.dist-tip` (CSS `:hover`, instant, no JS); for menus: the sidebar's `sb-sort-menu` in `teacher/ui.js` (`role="menu"`, `menuitemradio`). Every card keeps one height across its views and states.

## A. Student cards (`teacher/dash-student-cards.js`, `teacher/dashboard.css`)

1. **Chips with codes.** The strip (`.dash-card-strip`) draws one segment per column of `DashInsights.columns(cid)`. When the class has 8 columns or fewer, each is a 14 px chip showing a 2–3 letter code in 11 px / 600 text; with more, the strip stays the 6 px bars it is today (no code). Add `columnCode(cid, col)` to `teacher/dash-insights.js`: for a folder, the common letter prefix of its sections' first tag codes (`sec.tags[0].code`, e.g. `QP1`, `QP2` → `QP`); failing that, the initials of the first two words of its name (`Continuity & Change` → `CC`); for a section, its tag code without digits, else initials. Export it; part B's Needs Support header uses it.
2. **Chip colours.** Background `var(--score-N)` for the rounded level; text white, except Developing (level 2) uses `#2b1a00`-like dark text (contrast); not assessed: background `var(--divider-medium)`, text `var(--text-2)`.
3. **Instant pop-up.** Each chip holds a `.dist-tip` child (reuse the class; position it relative to `.dash-card-strip`, which gets `position: relative`, so it spans the card: `left: 8px; right: 8px; top: 100%`). Shown on `.dash-card-seg:hover .dist-tip` and `:focus-within`. Content: the column's full name; the level as `formatLevel(cid, value)` plus the level word in a Proficiency/Both class, or "Not assessed yet"; for a folder, "N of M competencies with evidence". Chips are `<button type="button">` with `aria-label` = that text, so keyboard users get it too. A click still opens the student page on Competencies (the strip's existing `data-student-tab="comps"`).
4. **Trend arrow moves to the header**, right after the grade badge and before the Missing count and the flag. Keep the existing rule (first half vs second half of counted evidence, ±0.2). `title`/`aria-label`: "Rising: later work scores higher than earlier work" / "Steady" / "Falling: later work scores lower than earlier work".
5. **No more "100% →".** Remove `.dash-card-meta`. The footer becomes a flex row: the observation line on the left; on the right, only when some competency has no scored evidence for this student, "N not assessed" in `--text-2`, 600 weight, `title="N competencies have no scored work yet"`. N counts tags (competencies), as `getCompletionPct` does.
6. **Focus hook for part B.** `renderStudentCards(cid, students, allStudents, sections, assessments, scores, flags, opts)` gains `opts.focusKey` (a column key). When set: that chip gets `outline: 2px solid var(--text); outline-offset: 1px`, the others `opacity: .35`; the footer's right side instead shows "<column label>: <level word>" in the level colour (600 weight); a card whose value on that column is below Proficient (same rule as the Needs Attention card, `DashInsights.readRule`) gets `border-color: color-mix(in srgb, var(--score-2) 55%, var(--divider-strong))`.
7. **Tests.** Update `tests/dash-card-trend.test.js` for the arrow's new place. Add `tests/dash-card-strip.test.js`: codes (prefix, initials, section code), chip vs bar at 8/9 columns, "N not assessed" shown only when N > 0, the tip's text, the focus hook. `e2e`: grep for `dash-card-meta` (none today); add one check in `e2e/dashboard.spec.js` that a Demo Mode card shows chips with codes and the tip text on hover.

## B. Curricular Competencies views and the page filter (`teacher/dash-overview.js`, `teacher/dash-insights.js`, `teacher/page-dashboard.js`, `shared/calc.js`, `teacher/dashboard.css`)

1. **The view menu.** The card title row gets a pill button after "Curricular Competencies": `.dash-view-btn` (24 px high, 12 px radius, `--divider-medium` border, faint background, the view name and a ▾). Click opens `.dash-view-menu` (`role="menu"`, `menuitemradio` buttons, each with the view name and a 12 px grey hint). Arrow keys move, Enter picks, Escape and a click outside close. `data-action="compView" data-view="…"`.
2. **Four views, in both grading styles.** State `compView` in page-dashboard, remembered per class on this device (`_readPref`/`_writePref`, key `fv-dash-comp-view:<cid>`). Default: `avg` in a Letter class, `mix` in a Proficiency or Both class (what each shows today). Every view has the same 16 px label row above the rows, so the card never changes height; the name column is 150 px (fits every competency name in the bank at 13 px); the value column 64 px.
   - **Class Average** (`avg`): today's bars; hint "The class average on each competency"; label row "Competency / Average"; value `formatLevel`.
   - **Level Mix** (`mix`): a table of four count cells per row from `competencyDistribution`, in `levelOrderFor(cid)` order, each cell `var(--score-N-bg)` / `var(--score-N-text)`, the row's largest count bold, an empty level a grey "–"; cells are the existing `data-action="mixSeg"` buttons so the students pop-up still opens. Value: "k of n" Proficient or above (n = scored students). Hint "How many students are at each level". This replaces `mixListHtml`'s segments; keep its "N Below" affordance as the row click (3).
   - **Needs Support** (`below`): one row per student among those below Proficient on at least one column (the Needs Attention rule, `DashInsights.belowLists`/`readRule`), the most columns first, at most 7 rows then "+N more" linking to the grid view; label row: the column codes (`columnCode`), "Student / Below"; cells: one 16 px cell per column, background `var(--score-N)` for the student's level, grey when not assessed; value "k of M". Hover tip: "Below on <names>". Click: open the student page. Hint "Students below Proficient most often, and where".
   - **Change** (`trend`): new `competencyMonthlyAverages(cid, studentIds, which)` in `calc.js` (**grade math, flag for Colin's review in the PR**): for each calendar month from the class's first counted score to today, each student's mean of their counted evidence (`getCountedTagScores`, score > 0) on the column's tags that month, then the class mean of those students; months with nobody scored are skipped. Row: an inline `<svg>` polyline across the row (`preserveAspectRatio="none"`, `vector-effect="non-scaling-stroke"`), green when the last month ≥ the first, red otherwise; value "↑ 12" / "↓ 8" in percentage points in a Letter/Both class (`levelToPercent`) or levels to one decimal ("↑ 0.4") in a Proficiency class, through calc.js helpers, never `toFixed` in the page. Label row: the first and last month names. Fewer than two months: the row shows "—" and the tip says "Not enough months yet". Hint "The class average month by month". Hover tip: "Sept 58% · Oct 64% · Nov 70%".
3. **Row click = the page filter.** Every row (all four views) is a button; clicking sets `naComp` (the existing "competency picked" state, which already filters the Needs Attention card) to that column key, or clears it when it is the same. Rows tint on hover (`rgba(0,0,0,.04)`), pointer cursor, `aria-pressed` on the picked row. Keep the `data-action="naComp"` name so `e2e/dashboard-layout.spec.js` (`.dash-mix-below`) keeps passing: keep a visually small "N Below" element in the Level Mix value cell for that spec, or update the spec to the new row control.
4. **What the filter does** (`naComp` set):
   - Needs Attention filtering: unchanged.
   - A filter bar above the Students header: chip "<label> ×" (`data-action="naComp" data-key=""` clears, `aria-label="Clear the <label> filter"`), the text "Weakest first", a button "Record an Observation for the N Below" (N and the ids from the Needs Attention rule; it opens the observation box with those students picked: check `openObsDialog`/`ObsCapture` for a multi-student option; if none exists, add an `opts.studentIds` preselect to the capture strip rather than inventing a new dialog), and the link "View <label> in Gradebook →" (`_gradebookHref`).
   - Cards sort by that column ascending (reuse `_gridSorted` with a derived sort; leave the teacher's `sortMode` untouched) and get `opts.focusKey` (A.6). The grid view sorts the same way.
   - Clearing restores everything. Escape clears the filter when nothing else is open.
5. **Motion.** Animate only what moved, never on first paint, and nothing when `prefers-reduced-motion: reduce` is on (a media query turns every rule below off).
   - **Cards slide to their new places** when the filter is set, cleared, or the sort changes: a FLIP step in page-dashboard — before re-rendering, record each `.dash-card`'s `getBoundingClientRect()` by student id; after the new HTML is in, for every card that was on screen before, set a `transform` from the old position to the new (`translate(dx, dy)`), force a layout read, then clear it with `transition: transform 250ms var(--ease-out)`. Cards that are new or gone just appear or vanish. Only do this for the student grid; nothing else on the page moves.
   - **Chip fade and the amber border** on the cards: `transition: background-color 200ms, color 200ms, border-color 200ms, outline-color 200ms` (A's `.dash-card-seg` and `.dash-card`).
   - **Switching a view on a card**: the rows crossfade in about 150 ms — the card gets `data-view`, and the row block fades in from `opacity: 0` on re-render (a class added after insertion). Bars keep their existing 300 ms width transition. No motion on numbers.
   - **Pop-ups appear at once** (no entrance). The view menu may fade in over 100 ms with a 3 px downward move, like the sidebar sort menu.
   - **The filter chip** appears in place; the bar beneath it does not slide.
6. **Tests.** `tests/dash-comp-views.test.js`: each view's markup for a Letter and a Proficiency class, the default view per style, the pref round-trip, the filter bar, the sort, `competencyMonthlyAverages` (two students, three months, a skipped month, both display units). `e2e/dashboard-comp-views.spec.js` in Demo Mode: open the menu with the keyboard, pick Level Mix, click a row, see the chip and the re-sorted cards, clear with the chip's ×.

## C. Core Competencies card (`teacher/dash-overview.js`, `teacher/page-dashboard.js`, `teacher/dashboard.css`, `teacher/styles.css`, `shared/` helper)

1. **Two views, same pill menu as B:** Self-Assessment (default when any student has one this term) and Evidence. With no self-assessment in the class this term there is no menu: "Evidence" as plain grey text beside the title, and the header link reads "Set Up a Reflection →" (to `/dashboard?course=<cid>&manage=questionnaires`). Otherwise the link is "Questionnaires →" (same target) in Self-Assessment and "Assignments →" (`/assignments?course=<cid>`) in Evidence. Remembered per class on this device (`fv-dash-core-view:<cid>`).
2. **The term and the data.** Move `_coreTermKeys` out of `teacher/page-student.js` into a shared helper (`shared/core-self.js`, loaded by `app.html` before the pages) as `coreSelfTerm(cid)` → `{terms, pick, key}`, and use it in both places. A student's rating for a core competency this term: the teacher-entered one (`getCoreSelf(cid)[sid][key][coreId].level`) first, else the student's own (`StudentVoice.coreSelf(StudentVoice.entries(cid, sid), pick.ordinal)[coreId].level`) when `StudentVoice.loaded(cid)`. If not loaded, `render()` calls `StudentVoice.load(cid)` once per class and re-renders when it resolves (a guard so it never loops).
3. **Rows.** Grouped by `cc.group` (Communication, Thinking, Personal & Social): a 3 px `--divider-medium` bar down the left of each group, 8 px between groups, no headings, no row lines; `title` on the bar names the group. Each row: the name (`cc.label`), the squares, the value (64 px, right-aligned).
   - **Self-Assessment:** one square per enrolled student (`flex: 1 1 0; min-width: 2px; max-width: 6px; height: 12px; gap: 2px`), Leading → Beginning first, then grey for the rest; `title` "Name: Confident" / "Name: not yet". New tokens in `styles.css`, light and dark: `--self-1` … `--self-4`, a light-to-dark blue (`#bfd6f6`, `#7fadea`, `#3c7fd6`, `#174f9c` in light mode), never the level colours. Value "k of N", amber (`--score-2-text`) when k < ⅔ N. Hover tip: "Leading 5 · Confident 9 · Growing 4 · Beginning 1" then "Not yet: names…" (first 8, then "+N more").
   - **Evidence:** one square per assessment tagged with the core competency (`a.coreCompetencyIds`, dark `--text-2`) then one per observation tagged with it (light `--divider-heavy`; find how an observation stores its tags in `getStudentQuickObs` entries / `obs-capture.js` and count across the class). Value: the total, or "None yet" in amber. Hover tip: the assessment titles, then "N observations"; when empty, "Tag work in Assignments, or an observation with + Add Tag".
4. **Tests.** `tests/dash-core-card.test.js`: both views, the no-self state and its link, the teacher-entered rating beating the student's, the ⅔ amber rule, evidence counts, the group bars. Update `tests/learner-profile.test.js`/student-page tests if the term helper's move touches them.
